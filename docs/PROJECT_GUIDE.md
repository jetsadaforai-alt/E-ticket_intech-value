## 1. โปรเจกต์นี้คืออะไร

แพลตฟอร์มตั๋วส่วนลดอิเล็กทรอนิกส์ที่ร้านค้าหลายร้านใช้ร่วมกัน (Multi-vendor) ร้านค้าสร้าง "อีเวนต์"
(แคมเปญส่วนลด) และออกตั๋วตามโควตาของแพ็กเกจที่ซื้อ ลูกค้ารับตั๋วเข้ากระเป๋าในแอป แล้วแสดง
**Dynamic QR Code** ที่เปลี่ยนรหัสทุก 60 วินาทีให้พนักงานหน้าร้านสแกนเพื่อใช้สิทธิ์ ข้อมูลการใช้สิทธิ์
ไปแสดงบนแดชบอร์ดของร้านทันที และมีเว็บหลังบ้านให้ผู้ดูแลระบบควบคุมทั้งแพลตฟอร์ม

ประกอบด้วย 3 ส่วน: **แอปมือถือ** (ลูกค้า / เจ้าของร้าน / พนักงาน), **เว็บหลังบ้าน** (Admin / SuperAdmin)
และ **Backend API** ที่ทั้งสองส่วนเรียกใช้

## 2. วัตถุประสงค์ด้านธุรกิจ (Business)

> "ทำไปทำไม" — ปัญหาที่แก้ ใครได้ประโยชน์ และระบบหารายได้อย่างไร

### ปัญหาเดิมที่ต้องการแก้

| ปัญหา | ผลกระทบ |
|---|---|
| ร้านขนาดเล็ก–กลางยังใช้คูปองกระดาษและตราปั๊ม | ถ่ายเอกสาร/ปลอม/ใช้ซ้ำได้ง่าย |
| ระบบตั๋วแบบเดิมใช้ QR แบบคงที่ | แคปหน้าจอแล้วส่งต่อให้คนอื่นใช้แทนได้ พนักงานแยกไม่ออก |
| พนักงานต้องตรวจและตัดยอดสิทธิ์เอง | ผิดพลาดง่าย ตัดซ้ำ ตัดผิด |
| ระบบใช้ได้เฉพาะร้านในเครือเดียว | ขยายไปร้านอื่นไม่ได้ ลูกค้าเข้าถึงโปรโมชันร้านอื่นในช่องทางเดียวไม่ได้ |
| ไม่มีข้อมูลสรุปการใช้สิทธิ์ | ร้านไม่รู้ว่าแจกไปเท่าไร ใช้ไปเท่าไร คิดเป็นมูลค่าเท่าไร วางแผนการตลาดไม่ได้ |
| แพลตฟอร์มตั๋วขนาดใหญ่ในตลาด | ซับซ้อนและแพงเกินไปสำหรับร้านขนาดเล็ก–กลาง |

### เป้าหมายทางธุรกิจ

- เป็นแพลตฟอร์มโปรโมชันที่ **ร้านอาหาร คาเฟ่ และผู้จัดงานขนาดเล็ก–กลาง** เปิดใช้เองได้ ไม่ต้องลงทุนระบบเอง
- **กันการทุจริตคูปอง** ด้วยการตรวจสอบอัตโนมัติ แทนการใช้สายตาของพนักงาน
- ให้ร้าน **ตัดสินใจจากข้อมูลจริง** ผ่านแดชบอร์ด (ตั๋วที่แจก ใช้ไป ส่วนลดรวม สินค้าที่ลูกค้าเลือก)
- **ขยายฐานลูกค้าให้ร้านแบบบอกต่อ** ผ่านการแชร์ตั๋วให้เพื่อน
- ใช้เป็นต้นแบบสำหรับต่อยอดเป็นผลิตภัณฑ์จริงในกลุ่มบริการบริหารสมาชิกและโปรโมชัน

### โมเดลรายได้

ร้านซื้อแพ็กเกจแบบจ่ายล่วงหน้าต่ออีเวนต์ (ไม่ใช่รายเดือน) — ลูกค้าปลายทางใช้ฟรี

| แพ็กเกจ | ราคา | สร้างอีเวนต์ได้ | ตั๋วต่ออีเวนต์ |
|---|---|---|---|
| Free | 0 ฿ | 1 | 5 |
| Copper | 59 ฿ | 3 | 10 |
| Silver | 199 ฿ | 5 | 50 |
| Gold | 350 ฿ | 8 | 100 |

- ร้านที่ได้รับอนุมัติเริ่มที่ Free ทันที ได้ลองใช้จริงก่อนจ่าย — ใช้หมดแล้วต้องอัปเกรด (Free เติมไม่ได้)
- แพ็กเกจเสียเงินเติมโควตาทีละอีเวนต์/ทีละชุดตั๋วได้ แต่ราคาเติมตั้งให้แพงกว่าซื้อแพ็กเกจราว 25%
  เพื่อจูงใจให้อัปเกรด
- ตั๋วที่ไม่มีคนรับเมื่ออีเวนต์จบหรือถูกยกเลิก คืนเข้าโควตาของร้าน (ร้านไม่เสียสิทธิ์ฟรี)
- ราคา/โควตาทั้งหมด SuperAdmin ปรับได้เองในเว็บหลังบ้าน

### ขอบเขตที่ตั้งใจยังไม่ทำ (ทางต่อยอด)

- ตั๋วแบบมียอดคงเหลือ เบิกใช้ทีละส่วน (แบบระบบฝากสินค้า)
- ผู้ประกอบการรายเดียวมีหลายสาขา และใช้ตั๋วข้ามสาขา (ตอนนี้ 1 ผู้ประกอบการ = 1 ร้าน)
- งานอีเวนต์ขนาดใหญ่ระดับคอนเสิร์ต (สแกนพร้อมกันจำนวนมาก หลายจุดทางเข้า)
- การใช้งานแบบออฟไลน์

## 3. วัตถุประสงค์ด้านผลิตภัณฑ์ (Product)

> "ระบบต้องทำอะไรได้" — ผู้ใช้ งานหลัก กติกา และสถานะปัจจุบัน

### ผู้ใช้และงานหลัก

| บทบาท | ช่องทาง | งานหลักที่ระบบต้องรองรับ |
|---|---|---|
| ลูกค้า | แอป | สมัคร/เข้าสู่ระบบด้วยเบอร์โทร + OTP · ดูอีเวนต์จากหลายร้าน · รับตั๋วเข้ากระเป๋า · แสดง QR ให้ร้านสแกน · แชร์ตั๋วให้เพื่อน · แชทถามร้าน · รีวิว · แจ้งปัญหา |
| เจ้าของร้าน | แอป (โหมดร้าน) | สมัครเป็นร้าน (รออนุมัติ) · ตั้งค่าร้าน · จัดการสินค้า · สร้างอีเวนต์ตามโควตา · เชิญพนักงาน · ซื้อแพ็กเกจ/เติมโควตา · ดูแดชบอร์ด/เปรียบเทียบอีเวนต์ · สแกนเองได้ |
| พนักงาน | แอป (โหมดพนักงาน) | สแกน QR ลูกค้า · เลือกสินค้าที่ลูกค้าใช้สิทธิ์ · ดูสรุปการสแกนวันนี้ · ตอบแชท |
| Admin | เว็บหลังบ้าน | อนุมัติ/ปฏิเสธ/ระงับร้าน · ระงับอีเวนต์ · ระงับผู้ใช้ · ตอบเรื่องร้องเรียน |
| SuperAdmin | เว็บหลังบ้าน | ทุกอย่างของ Admin · ตั้งราคา/โควตาแพ็กเกจ · จัดการบัญชี Admin · แดชบอร์ดภาพรวมระบบ |

ลูกค้า เจ้าของร้าน และพนักงาน **ใช้แอปเดียวและบัญชีเดียวกัน** (สลับโหมดในแอป) ส่วน Admin/SuperAdmin
ใช้บัญชีแยกของเว็บหลังบ้าน

### เส้นทางหลักตั้งแต่ต้นจนจบ

```
ร้านสมัคร → Admin อนุมัติ (ได้แพ็กเกจ Free) → ร้านสร้างอีเวนต์ (หักโควตา)
   → ลูกค้าเห็นอีเวนต์ → สมัคร/เข้าสู่ระบบ → รับตั๋ว (หรือรับจากเพื่อนที่แชร์มา)
   → เปิดตั๋วที่ร้าน (QR เปลี่ยนทุก 60 วินาที) → พนักงานสแกน → ยืนยันสินค้า (ถ้าอีเวนต์ผูกสินค้า)
   → ยอดขึ้นแดชบอร์ดร้าน
```

### กติกาสำคัญของระบบ

| กติกา | ค่า |
|---|---|
| ต้องสมัครสมาชิกก่อนจึงเข้าสู่ระบบได้ | เข้าสู่ระบบไม่สร้างบัญชีให้ |
| OTP | อายุ 5 นาที · ขอใหม่ได้หลัง 60 วินาที · ผิด 5 ครั้งล็อก 15 นาที |
| ตั๋วต่อคน | 1 ใบต่อ 1 อีเวนต์ต่อ 1 บัญชี (รวมตั๋วที่รับจากการแชร์) |
| Dynamic QR | รหัสสุ่มจากเซิร์ฟเวอร์ อายุ 60 วินาที แคปหน้าจอไปใช้ภายหลังไม่ได้ |
| ใช้สิทธิ์ | ครั้งเดียวจบ สแกนซ้ำถูกปฏิเสธ · ใช้ได้ภายในเวลาอีเวนต์และช่วงเวลาที่ร้านกำหนด |
| ส่วนลด | กำหนดต่อสินค้าได้ + ส่วนลดสำรองกรณีสินค้าหมด หรือลดทั้งร้าน |
| แชร์ตั๋ว | ลิงก์อายุ 24 ชั่วโมง ไม่มีคนรับ ตั๋วยังอยู่กับเจ้าของเดิม |
| พนักงาน | เชิญได้เฉพาะเบอร์ที่สมัครแล้ว · 1 ผู้ประกอบการ = 1 ร้าน |

### สถานะปัจจุบัน

| สถานะ | รายการ |
|---|---|
| ✅ ใช้งานได้ครบ | ทุกงานในตาราง "ผู้ใช้และงานหลัก" ด้านบน, แชท/Support แบบ real-time, หมดเวลาอีเวนต์อัตโนมัติ (คืนโควตา) |
| ⚠️ ระบบจำลอง | ส่ง SMS OTP (รหัสแสดงในแอปแทน) · การชำระเงิน (กดปุ่มจำลองจ่าย) — ต้องต่อผู้ให้บริการจริงก่อนเปิดใช้ทั่วไป |
| ⏳ ปุ่มที่ยังไม่ทำงาน | เข้าสู่ระบบด้วย LINE / Gmail · เปลี่ยนภาษา · ความเป็นส่วนตัว (กดแล้วขึ้น "เร็ว ๆ นี้") |
| 🔧 ควรปรับต่อ | สแกนแล้วตั๋วถูกใช้ทันทีก่อนยืนยันสินค้า · เทสต์ backend 8 ตัวต้องอัปเดต fixture (รายละเอียดใน HANDOVER.md) |
