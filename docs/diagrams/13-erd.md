# ERD — คู่มืออ่านฐานข้อมูลแบบละเอียด (ฉบับคนทั่วไปอ่านได้)

> อ้างอิงตรงจาก `backend/prisma/schema.prisma` (ฐานข้อมูลจริงที่ deploy อยู่) — 29 ตาราง
> ไม่มีตัวไหนตกหล่น ทุกคอลัมน์/ความสัมพันธ์เช็คกับไฟล์ schema จริงบรรทัดต่อบรรทัด

## อ่านยังไง (ศัพท์ที่ใช้ซ้ำในเอกสารนี้)

- **PK (Primary Key)** = คอลัมน์ที่เป็น "เลขบัตรประชาชน" ของแถวนั้น ไม่ซ้ำกับแถวไหนในตารางเดียวกันเลย ใช้ระบุตัวตนของแถว
- **FK (Foreign Key)** = คอลัมน์ที่ "ชี้นิ้วไปหา" แถวในอีกตารางหนึ่ง เช่น ตั๋วใบหนึ่งมีคอลัมน์ที่ชี้ไปหาว่า "มันเป็นของ event ไหน"
- **1 : 1** = 1 แถวฝั่งนี้ จับคู่กับอีกฝั่งได้แค่ 1 แถวเท่านั้น (เช่น 1 ร้านค้า มีได้แค่ 1 ร้าน)
- **1 : N** = 1 แถวฝั่งนี้ โยงไปหาอีกฝั่งได้หลายแถว (เช่น 1 ร้าน มีได้หลาย event)
- **N : M** = ทั้งสองฝั่งโยงกันได้หลายต่อหลาย (เช่น 1 event ผูกสินค้าได้หลายชิ้น และ 1 สินค้าก็ถูกผูกกับหลาย event ได้) — เวลาทำจริงในฐานข้อมูลจะต้องมี "ตารางเชื่อม" ตรงกลางเสมอ (ในเอกสารนี้คือ `VendorOwnership` และ `EventProduct`)
- **(ว่างได้)** = คอลัมน์นี้ไม่บังคับต้องมีค่า เป็น `null` ได้
- **(ห้ามซ้ำ)** = ค่าคอลัมน์นี้ต้องไม่ซ้ำกับแถวอื่นเลยทั้งตาราง (unique constraint)
- ชื่อคอลัมน์ในวงเล็บแบบ `snake_case` คือชื่อจริงในฐานข้อมูล (ที่เหลือคือชื่อในโค้ด ทั้งสองชื่อหมายถึงคอลัมน์เดียวกัน)

ตารางทั้ง 29 ตัวแบ่งเป็น 7 กลุ่มธุรกิจ:

1. ผู้ใช้ ร้านค้า และความเป็นเจ้าของ (8 ตาราง)
2. แอดมินและการตรวจสอบร้านค้า (2 ตาราง)
3. อีเวนต์และตั๋ว (9 ตาราง)
4. การแจ้งเตือน (1 ตาราง)
5. แจ้งปัญหา / Support (2 ตาราง)
6. แชทลูกค้า ↔ ร้านค้า (2 ตาราง)
7. แพ็กเกจและโควตา (5 ตาราง)

### 1.1 `users` — บัญชีผู้ใช้ทุกคนในระบบ (ลูกค้า/เจ้าของร้าน/พนักงานร้าน ใช้ตารางเดียวกันหมด)

| `email` | text | (ว่างได้) | อีเมล ไม่บังคับกรอก |

- ← `share_records` ในฐานะผู้แชร์ (1 : N) และในฐานะผู้รับแชร์ (1 : N)
- ← `redemptions` ในฐานะพนักงานที่สแกน (1 : N)
- ← `notifications` (1 : N) — แจ้งเตือนของตัวเอง
- ← `support_tickets` ในฐานะผู้แจ้งปัญหา (1 : N)
- ← `conversations` ในฐานะฝั่งลูกค้า (1 : N)
- ← `event_reviews` (1 : N) — รีวิวที่เคยเขียน

### 1.2 `vendors` — ร้านค้า/แบรนด์ (นิติบุคคลที่มาสมัครขายโปรโมชั่น)

| คอลัมน์ | ชนิด | PK/FK | คำอธิบาย |
|---|---|---|---|
| `id` | uuid | **PK** | รหัสร้าน (นิติบุคคล) |
| `name` | text | | ชื่อแบรนด์ |
| `verification_status` | text | | `pending` / `approved` / `rejected` — สถานะการตรวจเอกสาร ค่าเริ่มต้น `pending` |
| `status` | text | | `active` หรือ `suspended` — คนละแกนกับ `verification_status` (ถูกแบนได้แม้ผ่านการตรวจแล้ว) ค่าเริ่มต้น `active` |
| `suspended_at` / `suspended_reason` | วันเวลา / text | (ว่างได้) | รายละเอียดการระงับ |
| `suspended_by_admin_id` | uuid | **FK** → `admin_accounts.id` (ว่างได้) | แอดมินที่กดระงับ |
| `created_at` | วันเวลา | | วันที่สมัคร |

**เชื่อมกับตารางไหนบ้าง:**
- → `admin_accounts` (N : 1, ไม่บังคับ)
- ← `vendor_ownerships` (1 : N) — 1 ร้านมีเจ้าของ/หุ้นส่วนได้หลายคน
- ← `shops` (1 : 1, ไม่บังคับ) — **1 ร้านค้ามีได้แค่ 1 สาขา** (ตั้งใจไม่รองรับหลายสาขา)
- ← `vendor_verifications` (1 : 1, ไม่บังคับ)
- ← `vendor_quotas` (1 : 1, ไม่บังคับ) — โควตาปัจจุบัน
- ← `purchases` (1 : N) — ประวัติการซื้อแพ็กเกจ/เติมโควตา
- ← `quota_ledgers` (1 : N) — ประวัติการหัก/เติมโควตาทุกรายการ
- ← `vendor_documents` (1 : N) — เอกสารยืนยันตัวตนที่แนบไว้

### 1.3 `vendor_ownerships` — ตารางเชื่อม: ใครเป็นเจ้าของร้านไหนบ้าง

ตารางนี้มีไว้ทำความสัมพันธ์แบบ **N : M** ระหว่าง `users` กับ `vendors` (1 คนเป็นเจ้าของหลายร้านได้ และ 1 ร้านมีเจ้าของ/หุ้นส่วนหลายคนได้)

| คอลัมน์ | ชนิด | PK/FK | คำอธิบาย |
|---|---|---|---|
| `user_id` | uuid | **PK** (ร่วม) + **FK** → `users.id` | คนที่เป็นเจ้าของ |
| `vendor_id` | uuid | **PK** (ร่วม) + **FK** → `vendors.id` | ร้านที่ถูกเป็นเจ้าของ |
| `role` | text | | บทบาท ค่าเริ่มต้น `owner` |

*(ตารางนี้ไม่มีคอลัมน์ `id` เดี่ยว — ใช้คู่ `user_id + vendor_id` รวมกันเป็น PK แทน แปลว่า 1 คนกับ 1 ร้าน จับคู่กันได้แค่ 1 แถวเท่านั้น จะเป็นเจ้าของร้านเดียวกันซ้ำสองแถวไม่ได้)*

**เชื่อมกับ:** `users` (N : 1), `vendors` (N : 1) — ลบ user หรือ vendor ทิ้ง แถวนี้จะถูกลบตามไปด้วยอัตโนมัติ

### 1.4 `vendor_documents` — เอกสารยืนยันตัวตนที่แนบตอนสมัคร/อุทธรณ์

| `created_at` | วันเวลา | | วันที่แนบ |

| `ticket_balance` | ตัวเลข | | จำนวนตั๋วคงเหลือในกอง ค่าเริ่มต้น 0 |
| `event_balance` | ตัวเลข | | จำนวนสิทธิ์สร้างอีเวนต์คงเหลือ ค่าเริ่มต้น 0 |
| `updated_at` | วันเวลา | | อัปเดตล่าสุดเมื่อไหร่ |

**เชื่อมกับ:** `vendors` (1 : 1), `packages` ในฐานะแพ็กเกจปัจจุบัน (N : 1)

---

### 7.3 `purchases` — ประวัติการซื้อ (แพ็กเกจ / เติมอีเวนต์ / เติมตั๋ว)

| คอลัมน์ | ชนิด | PK/FK | คำอธิบาย |
|---|---|---|---|
| `id` | uuid | **PK** | |
| `vendor_id` | uuid | **FK** → `vendors.id` | ใครซื้อ |
| `type` | text | | `package` / `event_topup` / `ticket_topup` |
| `package_id` | uuid | **FK** → `packages.id` | อ้างอิงแพ็กเกจไหน |
| `package_code_snapshot` | text | | **สำเนา** โค้ดแพ็กเกจ ณ ตอนซื้อ (กันราคาเปลี่ยนย้อนหลังถ้าแอดมินแก้ `packages` ทีหลัง) |
| `unit_price_snapshot` | ทศนิยม | | สำเนาราคาต่อหน่วย ณ ตอนซื้อ |
| `quantity` | ตัวเลข | | จำนวนที่ซื้อ ค่าเริ่มต้น 1 |
| `amount_baht` | ทศนิยม | | ยอดเงินรวม |
| `ticket_quota_added` / `event_quota_added` | ตัวเลข | | โควตาที่ได้รับจากการซื้อครั้งนี้ ค่าเริ่มต้น 0 |
| `target_event_id` | uuid | **FK** → `events.id` (ว่างได้) | ถ้าเป็นการเติมตั๋วให้อีเวนต์ใดอีเวนต์หนึ่งโดยเฉพาะ จะระบุไว้ที่นี่ |
| `status` | text | | `pending` / `paid` / `failed` / `cancelled` ค่าเริ่มต้น `pending` |
| `created_at` / `paid_at` | วันเวลา | | |

**เชื่อมกับตารางไหนบ้าง:**
- → `vendors` (N : 1)
- → `packages` (N : 1)
- → `events` ในฐานะเป้าหมายการเติม (N : 1, ไม่บังคับ)
- ← `payments` (1 : 1, ไม่บังคับ)

---

### 7.4 `payments` — สถานะการชำระเงินของแต่ละคำสั่งซื้อ

| คอลัมน์ | ชนิด | PK/FK | คำอธิบาย |
|---|---|---|---|
| `id` | uuid | **PK** | |
| `purchase_id` | uuid | **FK** → `purchases.id` (ห้ามซ้ำ) | จ่ายเงินให้คำสั่งซื้อไหน — 1 คำสั่งซื้อมีได้ 1 การชำระเงิน |
| `provider` | text | | ผู้ให้บริการชำระเงิน (`mock` ตอนทดสอบ / `promptpay` ฯลฯ) |
| `amount_baht` | ทศนิยม | | ยอดที่ต้องจ่าย |
| `status` | text | | `pending` / `succeeded` / `failed` / `expired` ค่าเริ่มต้น `pending` |
| `provider_ref` | text | (ห้ามซ้ำ) | รหัสอ้างอิงจากผู้ให้บริการ — ใช้กันการยิง webhook ซ้ำแล้วเติมโควตาซ้ำสองรอบ |
| `payload` | JSON | (ว่างได้) | ข้อมูล QR/ลิงก์สำหรับให้ลูกค้าจ่ายเงิน |
| `created_at` / `paid_at` / `expires_at` | วันเวลา | (ว่างได้ยกเว้น created_at) | |

**เชื่อมกับ:** `purchases` (1 : 1)

---

### 7.5 `quota_ledgers` — บันทึกทุกครั้งที่โควตาถูกหัก/เติม (log ตรวจสอบย้อนหลังได้)

| คอลัมน์ | ชนิด | PK/FK | คำอธิบาย |
|---|---|---|---|
| `id` | uuid | **PK** | |
| `vendor_id` | uuid | **FK** → `vendors.id` | ร้านไหน |
| `ticket_delta` / `event_delta` | ตัวเลข (+/-) | | เปลี่ยนแปลงกี่หน่วย (บวก = เติม, ลบ = หัก) |
| `reason` | text | | `purchase` / `event_created` / `event_cancelled` / `event_expired` / `event_topup` / `admin_adjust` |
| `ref_id` | uuid | (ว่างได้) | อ้างอิงถึง `purchases.id` หรือ `events.id` แล้วแต่ `reason` (ไม่ได้บังคับด้วย FK เพราะชี้ไปคนละตารางได้) |
| `created_at` | วันเวลา | | |

*(คู่ `reason + ref_id` ห้ามซ้ำ — กันไม่ให้เหตุการณ์เดียวกันถูกหัก/เติมโควตาซ้ำสองรอบโดยไม่ตั้งใจ)*

**เชื่อมกับ:** `vendors` (N : 1)
